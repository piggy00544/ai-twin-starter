# SDK compatibility CI

The read-only reusable workflow runs on main pushes, pull requests, manual calls and twice daily (03:17 / 15:17 UTC). It reads the existing `compatibility.json` through the same validated compatibility script. An unavailable or unvalidated official npm latest fails closed; it never widens the supported range or publishes a package.

Each matrix job installs exact public SDK dependencies without lifecycle hooks into an isolated carrier. It runs the existing suite plus the real Cordis/HostConnection lifecycle/router contract. Finder uses the official JSON storage backend and DomainFacility; Twin uses the official ToolRuntime and native routes. No CLI/pnpm dependency, production profile, model call, message or real account is needed. Runtime code and descendants run in a hard OS network boundary (a Linux network namespace with privilege drop and no-new-privs, or macOS sandbox-exec), backed by a self-test of loopback, custom DNS lookup and non-Node child denial. The Node preload remains supplemental; dependency acquisition is a separate registry-only phase without product code or credentials. Unsupported or unavailable OS isolation fails closed; there is no unsandboxed runtime fallback.

`node scripts/ci-sdk.mjs --sdk 0.2.1-rc.5` runs the same command locally. `--plan` validates arguments and prints exact dependency versions without installing. Results go to an external temporary directory, or an explicitly selected external `DSH_CI_OUTPUT` directory. Runner, dependency installation, contract and inherited child Node options keep the 128 MB cap; Finder's suite runner and Node test workers retain their measured 512 MB baseline, while Twin's suite stays at 128 MB; the suite has a 240-second timeout, with shorter install/contract limits and bounded output; the workflow limits matrix parallelism to two.

The existing Trusted npm preparation job needs this reusable gate. Its explicit manual/main/repository/package authorization, OIDC placement and immutable artifact identity/hash checks remain unchanged. A local successful run does not claim that GitHub Actions has run. Published package versions and assets are unchanged by this CI-only patch.

TAP summaries must meet the retained substantive test minimum, pass every counted test and contain zero failures, skips, cancellations or todos. The reusable workflow rechecks latest after the matrix; the non-OIDC preparation job rechecks latest again immediately before packing. Publication continues to consume only the validated artifact.

The macOS profile explicitly permits network-bind for compatibility. The verified boundary is non-loopback outbound denial, including custom-lookup and non-Node children; this does not claim that the bind-address predicate alone restricts every possible listener address.
